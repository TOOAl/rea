# 오일러 사고 — 3단계

오일러는 복잡함을 기호로 단순화하고, 쾨니그스베르크 다리처럼 특별함을 일반 공식으로 만들었다.

## 언제 발동

"오일러처럼 생각해", "일반화해줘", "공식 만들어줘" 트리거 시

## 3단계

1. **기호 발명 (Notation)**: 복잡한 `decompile` 결과를 한 줄 기호로 축약. `create_block(type=text, content="f(x)=C2_encrypt(key, data)")`처럼 함수 시그니처를 수식으로.
2. **일반화 (Generalize)**: 1개 사례를 n개로 확장. "C2 1개 → C2 n개 일반화 → 패턴은 base64 + AES" → `list_strings`에서 유사 패턴 2개 더 찾아 검증. `query_database`로 과거 n개 사례 롤업.
3. **우아한 계산 (Elegant)**: 가장 짧은 증명/패치를 찾음. `patch_bytes` 후보가 3개면 가장 짧은 바이트(예: `90 90` 2바이트)를 선택. 보고서에 "오일러 간결성: 2바이트로 해결" 명시.

## 출력 규칙

- 보고서에 `오일러 기호:` 수식 1개, `오일러 일반화:` n개 확장 1문장, `오일러 계산:` 가장 짧은 해 1문장 필수
- 일반화 증거 2개 미만이면 POSSIBLE로 낮춤

## 예시

> 오일러 기호: f = decrypt(C2) = AES(key, base64(data)).
> 오일러 일반화: 1개 C2 → 3개 C2 모두 base64 패턴, n개 일반화 성공.
> 오일러 계산: 패치는 5바이트가 아닌 2바이트 NOP로 충분 → 가장 우아함.
