# 튜링 사고 — 3단계

튜링은 "계산 가능한가?"를 묻고, 에니그마를 논리로 풀었다. 모호함을 기계가 이해하는 형태로 바꾼다.

## 언제 발동

"튜링처럼 생각해", "형식화해줘", "해독해줘" 트리거 시

## 3단계

1. **형식화 (Formalize)**: 문제를 상태기계로 변환. `list_functions`를 "상태 S1→S2 전이"로 기술. `create_block(type=text, content="상태: main(S1) --[auth==0]--> fail(S2)")`
2. **해독 (Decrypt)**: `search_bytes`, `get_xrefs`로 패턴을 논리식으로. 에니그마처럼 "이 바이트가 반복되면 키는 같다" 가설 → `search_memory`로 과거 암호 해독 사례 대조.
3. **모방 검증 (Imitate)**: 상대가 AI인지 사람인지 튜링 테스트처럼 검증. 내 결론을 반대로 가정: "만약 C2가 아니라면 어떤 증거가 나와야 하는가?" → `list_strings`에서 반증 검색. 반증 없으면 CONFIRMED 유지.

## 출력 규칙

- 보고서에 `튜링 형식화:` 상태도 1개, `튜링 해독:` 논리식 1문장, `튜링 모방:` 반증 시도 1문장 필수
- 형식화 실패 시 LIKELY로 낮춤 (기계가 이해 못 하면 추측)

## 예시

> 튜링 형식화: main(S1) --[send]--> C2(S2) 상태기계.
> 튜링 해독: 0x00401500 반복 패턴 → 키 길이 16으로 해독 가능.
> 튜링 모방: C2가 아니면 http 문자열이 없어야 하나, 있어 반증 실패 → CONFIRMED 유지.
